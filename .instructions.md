## Authorization Rules

### Blog
- Any authenticated user can create articles
- Only article author can edit/delete their own articles
- Only admin can approve/reject articles
- Public can view only approved articles

### Komunitas
- Any authenticated user can create communities (pending status)
- Creator can edit their community
- Only admin can approve/reject communities
- Only approved communities show in public list
- Members can join/leave (not creator)
- One user cannot join same community twice (unique constraint)

## API Routes

### Public Community Routes
- `GET /komunitas` - List approved communities
- `GET /komunitas/buat` - Create form
- `POST /komunitas` - Store new community
- `GET /komunitas/{community}` - View community detail
- `POST /komunitas/{community}/join` - Join community (auth required)
- `POST /komunitas/{community}/leave` - Leave community (auth required)

### Admin Community Routes
- `GET /admin/communities` - List all communities with filter
- `GET /admin/communities/{community}/edit` - Edit form
- `PUT /admin/communities/{community}` - Update community
- `DELETE /admin/communities/{community}` - Delete community
- `POST /admin/communities/{community}/approve` - Approve
- `POST /admin/communities/{community}/reject` - Reject

## Important Notes
1. Community status has THREE states: pending, approved, rejected
2. Members count is incremented/decremented when users join/leave
3. Creator is automatically added as first member when creating
4. Icon upload is optional, uses Cloudinary or local storage
5. Blog author system uses auth()->id() relationship to User model
6. All authorization checks done both frontend AND backend
7. Use existing layouts.app and layouts.admin templates
8. Follow existing design patterns from Blog feature
